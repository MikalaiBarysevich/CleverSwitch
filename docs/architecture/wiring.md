# Wiring

`setup/app_setup.py:setup_context()` creates Topics, LogiDeviceRegistry, the DeviceCache (see [device-model.md](device-model.md)), and all subscribers. It is the single place where components are connected. The one exception is the I/O side: `discovery.discover()` builds the `HotplugBackend`, the optional edge-switch backend and `LinkManager`, and `discovery/link_factory.py:create_link()` builds each `DeviceLink` with its HID channels, optional `GattChannel`, `EventListener` and `WriteRouter`, and holds all platform / connection-type branching.

Active subscribers: `DeviceConnectionSubscriber`, `DeviceInfoSubscriber`, `InfoTaskOrchestrator`, `SetReportFlagSubscriber`, `ExternalUnsetFlagSubscriber`, `AnalyticsRejectionSubscriber`, `HostChangeSubscriber`, `EasySwitchKeySubscriber`, `ChangeHostNotificationSubscriber`, `EventHookSubscriber`, `WirelessStatusSubscriber`, `TransportDisconnectionSubscriber`, `ReceiverArmingSubscriber`, `DirectDeviceConnectionSubscriber`, `ChannelRearmSubscriber`, and `EdgeSwitchSubscriber` (only when `edge_switch.enabled`).

The parser leaves ES CID presses as plain `HidppNotificationEvent`s; `EasySwitchKeySubscriber` turns one into a `HostChangeEvent` (fn=0 diverted, fn=2 analytics press-only) only when its feature index is the device's resolved 0x1B04 index, so another feature's event with the same leading bytes cannot switch hosts. `HostChangeSubscriber` reacts to `HostChangeEvent` and sends CHANGE_HOST to all registered devices.

`EventHookSubscriber` listens on `hid_event` for `HostChangeEvent` and `DeviceConnectedEvent`, and fires user-configured hooks asynchronously via `hooks.py`. Hooks are a named mapping in config (`HooksConfig.hooks: dict[str, HookEntry]`); each entry declares an explicit `path` (run directly, no shell) **or** `command` (run via shell) — never both — plus one or more `type`s (`CONNECT`/`SWITCH`/`DISCONNECT`, scalar or list) and a `timeout`. `HooksConfig.for_type(HookType)` selects the entries an event fires. By default hooks only fire for keyboard events; set `hooks.fire_for_all_devices: true` in config to include mouse events. This global default is overridable per hook via the nullable `HookEntry.fire_for_all_devices` (`None` inherits the global; `True`/`False` widens/narrows just that hook), resolved in `hooks.fire()`. Tracks per-wpid last connection state internally (under a lock) to avoid double-firing hooks from duplicate connection events (e.g. Windows multi-collection re-enumeration). DISCONNECT fires only when the last recorded state for the wpid is connected, so a paired device the receiver enumerates as off at startup or re-plug (found via the cache) fires nothing. CONNECT needs the device's name and role, which a connect event does not always have yet: the device is looked up in the cache as well as the registry (at startup `DeviceConnectionSubscriber` may not have registered the cached device yet — they drain on separate threads), and the subscriber also listens on `info_progress`, firing CONNECT once a connected device's discovery gives it a name and role.

`TransportDisconnectionSubscriber` listens on `hid_event` for `TransportDisconnectedEvent`; for each registered device whose pid matches the dropped transport, it publishes `DeviceConnectedEvent(link_established=False)` so per-device subscribers react as if each device sent a normal disconnect.

`ExternalUnsetFlagSubscriber` detects when an external app (Solaar, logiops) clears the ES key reporting flag via `setCidReporting` (fn=3, sw_id in 1–7). The parser emits `ExternalUnsetFlagEvent`; the subscriber re-publishes `SetReportFlagEvent` to restore the flag. **Known limitation**: it only sees a peer's `setCidReporting` if that peer shares our transport, and `parser.py` only classifies one as external for sw_id 1–7. On BLE a peer typically arms over HID, so this subscriber has never been observed firing there.

`AnalyticsRejectionSubscriber` detects keyboards that advertise `KEY_FLAG_ANALYTICS` in getCidInfo but silently reject the analytics enable: the device echoes our `setCidReporting` request (sw_id=`SW_ID_DIVERT`, fn=3) with byte 9 cleared to 0x00 instead of the requested 0x03 (observed on the K850). Per the HID++ 2.0 0x1B04 spec, the response is a verbatim echo, so byte 9 = 0x00 is a definitive rejection signal — provided byte 2 (divert flags) is 0x00 as in our request; a non-zero byte 2 is a peer app's divert request sharing `SW_ID_DIVERT`. The subscriber discards `KEY_FLAG_ANALYTICS` from `device.supported_flags`, persists the change via `DeviceCache.save`, and re-publishes `SetReportFlagEvent`; `SetReportFlagSubscriber` then naturally takes the divert branch on the retry.
