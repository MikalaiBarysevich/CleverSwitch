# Edge switch

Optional second way to start a switch (`edge_switch` config section, off unless present): with exactly the configured modifiers held (`Modifier` flag; left/right merged) and no mouse button down, the cursor moving onto a mapped outer edge of the desktop switches every device to that edge's host.

```
EdgeBackend thread ──EdgeTouchedEvent(slot=0, pid=0, edge)──▶ topics.edge
EdgeSwitchSubscriber ── edge → host (0-based) ──▶ topics.hid_event: HostChangeEvent(0, 0, host, source=EDGE)
HostChangeSubscriber (unchanged, the only CHANGE_HOST sender) ──▶ every device with 0x1814
```

- **Lifecycle**: `discovery.discover()` calls `edgeswitch/backend_factory.start_edge_switch()` after the hotplug backend starts, and stops the edge backend first in its `finally` (each shutdown step through `_run_quietly`, so one failure cannot skip the rest), before `_undivert_all`. `EdgeSwitchSubscriber` and `HostChangeSubscriber` also refuse work once the shutdown event is set, so an event already queued when the backend stops cannot send a switch after the keys were un-diverted. Only KDE and GNOME refuse a second edge backend (the D-Bus name); nothing coordinates two daemons elsewhere, so one instance per machine is assumed. A backend that cannot start (missing permission, no X server yet) is still returned: `EdgeBackendReviveSubscriber` calls `revive()` on every `DeviceConnectedEvent(link_established=True)`, which restarts it if its thread is not running — the same path recovers a loop that lost its input source. Nothing retries on a timer. A malformed `edge_switch` section logs an error and leaves the feature off; nothing in it ever stops the daemon.
- **Nothing polls.** Every backend is a `LoopEdgeBackend` (`loop_backend.py`) running an `InputLoop` that blocks on its OS's input events:
  - The loop is built on the backend thread by a `LoopFactory(publish, stopping)`, so its OS connection belongs to that thread. `run()` dispatches until interrupted and raises when the source is lost; `interrupt()` is sticky and callable from any thread; `close()` runs on the backend thread only. `interrupt()` is only called while the loop is registered and `close()` only after it was unregistered under the same lock, so a stop can never write to a closed fd. A start that times out marks its attempt stopping and forgets it, so a later revive starts a fresh attempt instead of being turned away by `is_alive()`; the abandoned thread closes the loop if the factory returns late.
  - `EdgeSink` (`edge_sink.py`) joins a loop to `EdgeDetector`: the cursor is looked up (an OS call) only for a motion event while the gesture is held, and nothing is published while stopping.
  - **Windows** `windows/raw_input_loop.py`: Raw Input (`RIDEV_INPUTSINK`, mouse + keyboard) to a message-only window, `GetMessageW` loop, stopped by `PostThreadMessageW(WM_QUIT)`. Not low-level hooks: Windows silently removes a hook whose (GIL-bound) callback is slow, and it lags the cursor. A `WM_INPUT` only says something happened; key/button state (`GetAsyncKeyState`), `GetCursorPos` and the virtual-screen metrics (per-monitor DPI v2) are read once per burst, when `GetQueueStatus(QS_RAWINPUT)` shows the queue drained.
  - **macOS** `macos/event_tap_loop.py`: a listen-only `CGEventTap` on the thread's CFRunLoop (needs Input Monitoring, which CleverSwitch already needs; checked with `CGPreflightListenEventAccess`). Each mouse event carries location and flags. A tap disabled by timeout/user input is re-enabled at once; if that fails the loop ends. Stopped by a version-0 run-loop source.
  - **Linux** `linux/desktop.py:linux_loop_factory` picks the reader at every start attempt, so a revive finds a desktop that appeared later. X11 first: `DISPLAY` set, no `WAYLAND_DISPLAY`, `XDG_SESSION_TYPE` not `wayland`, and a server without the `XWAYLAND` extension (XWayland's pointer only moves over X windows; a systemd unit may import just `DISPLAY` into a Wayland session). Then Hyprland, then the session bus: `org.kde.KWin` → KDE, `org.gnome.Shell` → GNOME (found on the bus, not from `XDG_CURRENT_DESKTOP`, which systemd units often lack). Anything else raises `EdgeSwitchError` with the session type, logged as unavailable (plus an import-environment hint when `DISPLAY` is missing). A Hyprland session whose IPC socket is missing or silent gets its own message instead, since that is a fixable setup problem rather than an unsupported desktop. No push gesture: a desktop that does not share the cursor position gets no edge switch.
  - **Linux, X11** `linux/xinput_loop.py`: XInput 2.1+ raw key, button and motion events on the root window over libxcb (`linux/xcb.py`, not Xlib, whose I/O error handler calls `exit()`); `x11_events.py` decodes them (the raw event's detail is at offset 16), `x11_keymap.py` maps keycodes to modifiers. Needs no `/dev/input` access. Modifiers, buttons and the cursor are read from the server once per burst; bounds are the root window, updated from its `ConfigureNotify` (RandR resizes it). A lost connection raises.
  - **Linux, KDE and GNOME** report edge *sets* over the session bus (`linux/edge_bus.py`; jeepney glue in `linux/session_bus.py`). CleverSwitch owns `io.github.mikalaibarysevich.CleverSwitch` (`RequestName` DO_NOT_QUEUE, so a second instance is refused) and serves `…EdgeSwitch.Edges(u mask)` (1 left, 2 right, 4 top, 8 bottom; KWin may send it as a double) and, for GNOME only, `State(u clutterMods)`. Only the compositor's unique name, resolved at start, may call; others get AccessDenied. Every match rule is added before `RequestName`, which is what the peer reacts to, and the peer leaving the bus raises. `SessionBus.call` keeps messages that arrive before its reply — never use jeepney's `send_and_get_reply`, which drops them. `EdgeSink.on_edges` stores the last set and feeds it again after each state change, so the arming rule holds without positions.
    - KDE (`linux/kwin.py`): `LibinputLoop` with a `KWinCursor` feed. The KWin script (a string in `kwin.py`, written to a private temp file) reports edge changes from `workspace.cursorPos`; it is unloaded before loading (a killed daemon's copy) and on close. Plasma 6 only (`/Scripting/Script<id>`). KWin scripts cannot see modifiers, so keys come from libinput.
    - GNOME (`linux/gnome_shell.py`, extension in `gnome-extension/`): `GnomeShellLoop`. The extension tracks the cursor (`position-invalidated`) only while our name exists and samples `global.get_pointer()` per motion, so a modifier change without motion waits for the next motion. Its state is probed before start (`GetExtensionInfo`, `UserExtensionsEnabled`) with a README hint per failure, and `ExtensionStateChanged` away from active raises. No `/dev/input` needed.
  - **Linux, Hyprland** `linux/libinput_loop.py`: one libinput context through ctypes (`linux/libinput.py` on libinput.so.10 + libudev.so.1; the binding turns each event into a plain `LibinputEvent`). libinput finds devices on our seat (`XDG_SEAT`, else `seat0`), follows hotplug through its own udev monitor and opens each through our `open_restricted` — read-only, never raising (an exception there would hand libinput fd 0) — so it reads exactly what the process may read. The cursor comes from a `CursorFeed` the loop owns (Hyprland's locator or `KWinCursor`). It works like the Windows loop: `linux/hyprland_locator.py` stands in for `GetCursorPos` — `j/cursorpos` and `j/monitors` (logical union, scale and rotation applied) once per motion burst while the gesture is held, so a monitor change mid-hold is seen — feeding `EdgeSink` → `EdgeDetector`. Each request connects, asks, reads to EOF and closes: Hyprland serves the socket synchronously and freezes on a connection left open. The socket is found from `HYPRLAND_INSTANCE_SIGNATURE`, then by scanning `$XDG_RUNTIME_DIR/hypr` newest first (a systemd unit may lack the variable; a restart changes it). A Hyprland that stops answering makes `locate()` raise, which ends `run()`; the backend is revived on the next device connection. Held modifiers and buttons come from libinput's seat-wide count per key code (`seat_state.py`), so Ctrl held on two keyboards stays held until both release it; the seat is `XDG_SEAT` or `seat0`, and relative and absolute motion both trigger a cursor lookup. libinput releases a removed device's keys before `DEVICE_REMOVED`, and clearing the state when the last keyboard or pointer goes is only a safety net. Needs part 2 of `rules.d/42-cleverswitch.rules` (Logitech `/dev/input` nodes, also virtual ones with Logitech's vendor id) or the `input` group; with nothing readable it warns once and keeps listening, and a permission granted later needs a restart (libinput does not retry a refused node). A remapper's exclusive grab (OpenLogi, keyd) silences the real device; its virtual device must be readable instead. Never log key codes.
- **Diagnostics** (`edge_detector.py`): at DEBUG it traces every state change (modifiers, whether they match, buttons, active), an edge ignored because it was already under the cursor at the start of the gesture, a cooldown hit, and each fire — log-on-change, so motion does not flood the log. Each loop names its reader at INFO on start, which is what the README's troubleshooting section keys on.
- **Detector rules** (`edge_detector.py`): an edge is armed only once the cursor has been seen off it during the current held period, and fires on entry. That stops a bounce back — the keyboard arrives on the other host with the modifier still down while that host's cursor may sit on the edge leading back. After firing, the detector stays latched until the modifiers stop matching, so one hold switches once. A touch inside the cooldown disarms that edge until the cursor leaves it.
- **Hooks**: `HostChangeEvent.source` (`SwitchSource.DEVICE` default / `EDGE`). For an edge switch `EventHookSubscriber` reports a representative device (a named keyboard first, connected before disconnected, then a named mouse — keyboard first so keyboard-only hooks still fire); `fire_switch` sets `CLEVERSWITCH_SWITCH_SOURCE`. An edge switch with no registered device supporting 0x1814 fires no hook: nothing was switched, and a hook would report something that never happened.
- **Echo guard**: `SwitchEchoGuard` (`model/switch_echo_guard.py`) is shared by `EdgeSwitchSubscriber` (records the target) and `ChangeHostNotificationSubscriber`, which drops an x1814 announcement of the same target within 2 s. Whether devices announce a switch they were told to make is unconfirmed; the guard keeps it from causing a second switch burst and a second SWITCH hook. A genuine press to that same host inside the window is dropped too — acceptable, because every device was just told to go there, so only a redundant repair is lost; a press to any other host passes at once.
- **Known risk**: the switch is sent while the modifier is held, so the departing host may never see it released (the user accepted this).
